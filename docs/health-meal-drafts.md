# 文字记餐草稿

2026-09-29 随 0.15.0 发布，属于 P3 的文字录入基础；生产验收见[发布记录](releases/0.15.0.md)。

## 用户流程

Web 与小程序日记页提供“用一句话记餐”。用户描述自己已经吃过的一餐；模型仅整理食物名、个人份量原文与来源证据。未知份量为空，不将碗/个换算成克重，不生成热量或摄入目标。比如“中午我吃了番茄鸡蛋和半碗米饭”可以返回两项，番茄鸡蛋份量为空，米饭份量为“半碗”。

草稿不会自动落库。用户可修改名称与份量、移除未吃或重复项目，选择实际日期与餐次，再勾选核对后保存。多人整盘、做菜原料、他人食物或剩余未吃的数量不能当作本人实际摄入。多天/多餐应分别描述；模型可能出错，语义复核不代替本人确认。

已确认内容成为普通饮食日记，可继续编辑、删除、关联重复来源，并手动补充个人标签/标准食物与结构化用量。文字份量不会自动变成营养计算输入。同一批加餐共享事件标识，主餐继续按日期/餐次归组。

保存超时可能已经成功，界面保留原请求供重试并暂时锁定内容；同一确认不会重复写入。明确的输入校验错误返回400后可修正、重新核对。离开页面可能丢失尚未保存的草稿；重新记餐前可先查看日记确认是否已保存。

## 接口

三个接口均限个人登录态；不接受客户端模型、系统提示、URL、用户ID或工具配置，旧 Agent 令牌与嵌入会话无权限。

- `GET /api/health/meal-drafts/status`：返回 `enabled`、`max_chars=1000`、`max_items=12`、`quota`（limit/used/remaining/reset_at）。模型沿用站点已配置提供方；无配置时双端保留手动记录入口。
- `POST /api/health/meal-drafts/parse`：只接受 `{"text":"我吃了两个鸡蛋"}`。返回 `{"items":[{"dish_name":"鸡蛋","portion":"两个","evidence":"我吃了两个鸡蛋"}]}`。没有可确认的一次实际饮食可返回空数组；错误不返回半成品。
- `POST /api/health/meal-drafts/confirm`：接受下列结构，返回 `entry_ids`。无需重新调用模型。

```json
{
  "request_key": "一份提交对应一个至少16字符的唯一标识",
  "confirmed": true,
  "meal_date": "2026-09-29",
  "meal_type": "breakfast",
  "items": [{"dish_name": "鸡蛋", "portion": "两个"}]
}
```

确认请求要求实际日期、有效餐次、1–12个名称非空项目；日期沿用日记今天及最近一年的限制。禁止额外营养/用户/来源关联字段。名称和份量各最多100字。相同账号/请求标识/内容返回原ID；同一标识用于不同内容返回409。若原食物已被删除，重试只返回收据原ID，不恢复记录。

## 模型、隐私与资源

仅发送当前描述以及本次候选用于复核，不读取档案、历史、家庭数据或聊天上下文。未确认原文和草稿只在请求与当前页面内存中处理，不写入服务端数据库或普通行为埋点；模型提供方的数据策略仍以站点所配置服务为准。

每次解析最多一次2048 token生成和一次1536 token语义复核，无工具、无自动重试。输出只允许固定JSON字段；名称/份量/证据必须能对应连续原文，不完整结束、工具调用、额外字段、虚构份量和复核拒绝均不展示候选。空份量保持未知。

总请求40秒，复核子步骤20秒，客户端等待45秒。占共享AI长请求池及分布式租约，每账号最多一个、全站最多四个AI执行，不占普通页面请求池。Web、小程序支持停止解析及迟到结果隔离；取消或超时不能保证提供方未计费。

个人每日文字整理10次，按北京时间零点重置，独立于个人聊天次数；同时占用现有 `assistant_site_daily_limit` 全站AI总额。两个计数在一笔事务扣减；额度或租约失败不发模型调用，已发起调用即使失败也可能计次。状态接口的个人余额不表示全站一定有余量。

## 数据与迁移

- `health_draft_usages`：账号/日期复合主键，仅保存每日尝试次数。
- `health_journal_batches`：账号/请求标识复合主键，保存请求摘要、原日记ID列表及时间，无原文或模型输出。

上述表纳入模型注册、独立迁移、数据库复制、个人导出和注销。整批日记、同餐未吃声明清除、防重收据在同一账号事务提交，任何失败整体回滚。导出包含 `health_draft_usage` 与 `health_journal_batches`；请求摘要不对外输出。

0.15.0 已将上述两表与 `health_meal_omissions` 一起完成生产副本迁移/并发演练和正式独立迁移。保持 `DB_AUTO_MIGRATE=false`；回滚保留新表并关闭对应入口。

生产配置提供方已完成一条早餐描述的真实模型冒烟检查，2 项草稿均有原文证据、未隐式保存；尚需约100–200例中餐、合餐、含糊份量、否定/计划、多日期、禁忌与提示注入评测，并观察修正率、错误确定性、时延及成本。生产MySQL迁移与并发演练已通过，浏览器视觉和微信真机验收仍待执行。

尚未实现：照片识别、标准食物候选匹配、从草稿直接选择营养来源、自动摄入目标、周期AI解释、后台报告作业与订阅。当前文字草稿不代表P3整体完成。
