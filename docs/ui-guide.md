# Web 与小程序界面规范

## 方向与范围

品牌统一为 **arre食谱推荐小助手**。Web 与小程序默认采用青柠背景、奶白卡片、深橄榄文字与胶囊按钮；同时提供暖桃、海盐蓝、莓果配色。两端使用一致的名称、信息顺序、空状态与操作文案。技术包名、接口标识和存储键中的 `ninimenu` 保留兼容。

登录页以原生小程序的布局和操作为参考；平台原生的微信授权、导航栏和键盘各自适配。真机渲染差异需要在微信体验版核验，组件模拟不能证明像素完全一致。

## 颜色与文字

Web 配色源文件为 `frontend/src/themes.css`，`frontend/src/index.css` 注册 Tailwind 语义色并保留全局基础样式。小程序颜色源文件为 `miniprogram/app.wxss` 与 `miniprogram/utils/theme.js`。后续页面使用语义变量，避免局部写死只适合浅色的文字、背景或图标。

### Web 页面主题

- 四套配色均支持浅色、深色、跟随系统；默认青柠 + 跟随系统，用户手动选择优先于系统。
- 首页顶栏、登录页「换肤」与「我的 → 偏好设置 → 页面主题」打开同一个主题面板。选择即时生效，关闭面板不撤销选择。
- 偏好保存在当前设备的 `ninimenu_appearance`，跨同源标签页同步；不写入账号设置，不跨设备同步。存储不可用时仍即时换肤，并说明无法保存。
- HTML 启动脚本在首屏绘制前恢复主题；应用接管后持续响应系统和存储变化。修改主题枚举、默认值或启动底色时，需同步 `frontend/index.html` 与 `appearance.ts`，运行 `scripts/tests/appearance.test.cjs`。
- 标准内容卡片 28 px，首页主推荐卡片 32 px（桌面 40 px），按钮使用胶囊圆角。推荐详情使用淡色双线票券，有菜图时展示真实菜图，无图时直接展示文字票券。
- 青柠主按钮使用 `#9DCD19` 背景与 `#304300` 文字，保留参考图的明亮绿色并确保小字号可读。其他主题分别配置文字与按钮底色。

| 页面背景 | `#C4E38B` | `#161D10` |

### 小程序主题同步

- `utils/theme-palettes.js` 与 Web 的配色令牌一致，客户端测试逐项核对。`utils/theme.js` 负责持久化、系统事件、原生导航及下拉刷新颜色。
- 全部 25 个页面用 `theme.page()` 注册，在根部放置 `page-meta`。包装器保留原生命周期，并在卸载时移除监听；新增页面必须遵守这个约定。
- 首页问候区、登录页和「我的 → 外观」共用 `components/theme-picker`。选择即时更新页面、SVG 图标、转盘、弹层与自定义底栏；手动模式优先于系统。Web 和微信存储相互独立，不自动跨端同步偏好。
- 换肤面板通过微信 `root-portal` 脱离滚动/动画容器，再复用 `sheet` 的底栏锁，防止父容器裁切。原生系统选择器、键盘、授权弹框的外观仍由微信/系统控制。
- `app.wxss` / `theme.json` 提供默认青柠首帧兜底；`page-meta` 内联令牌恢复已保存的选择。缓存损坏或不可用时降级为默认值，写入失败会明确提示。

- 使用系统中文字体；正文优先 14–16 px，小程序按 375 px 屏宽以 2 rpx ≈ 1 px 换算。
- 重要动作、错误和输入标签不使用低对比度的占位符颜色。
- 长菜名、长昵称和错误说明允许换行；需单行截断的导航标题保留完整可访问名称。
- 主要操作点击区域至少 44 px / 88 rpx，图标可以小于点击区域；按钮等待时同时禁用并显示进度。

## 页面与导航

- 首页聚焦选菜，菜谱页聚焦浏览和我的私房菜，记录页聚焦回顾，「我的」集中账户入口。
- `/plan` 和小程序一周菜单页集中展示菜单与买菜清单，移除重复的个人设置和成就预览。
- 普通用户仅在本人/有权编辑的家庭菜谱看到修改入口。私房菜列表与分类数量都使用相同 `scope=mine`。
- Web 主要页按需加载，导航容器不对整屏使用 `transform`，防止固定弹层被父容器约束。
- 登录页与「我的」均提供关于我们入口；特色、用法、常见问题与协议可公开阅读。
- 站内信点击即展示一层详情；详情不能再次打开同类详情或跳回自身。

## 弹层、键盘与焦点

Web 共用 `AnimatedBottomSheet`、`use-dialog`，小程序共用 `components/sheet`、`utils/sheet-tabs`。

- 表单弹层采用实底内容区；毛玻璃仅作为导航等辅助材质，不能影响按钮和输入可读性。
- 小程序弹层打开时隐藏真实 `custom-tab-bar`，关闭动画结束后再恢复；离开页面、重复开关或多弹层并存都由锁管理。
- 键盘高度和安全区共同决定底部留白，不能靠不断抬高 `z-index` 处理遮挡。
- Web 打开后将焦点置于弹层内，Tab 循环、Escape 关闭，结束后恢复到触发控件；弹层显示期间锁定背景滚动。
- 提交失败保留已填信息并允许重试，成功后同步个人信息缓存，再关闭弹层。

## 请求与表单状态

- Web 用 `RequestState`，小程序用 `request-state`，区分加载、确实为空、请求失败和重试中。
- 失败不能渲染成“暂无内容”或当成退出登录；仅认证过期触发重新登录。
- 旧账号的异步响应不能覆盖新账号状态；偏好表单进入编辑后，后台刷新不能覆盖未保存内容。
- 日期范围中的记录读取全部分页后再计算日历/统计，不能把第一页当完整结果。
- 图片上传中禁止提交；失败时保留文字和已成功上传的图片，不自动清空表单。

## 食谱自动草稿

这是本轮原定解决的新增痛点：长食谱在误返回、切后台或保存失败后丢失。后续追加的关于我们、助手额度和安全任务单独记录在进度文档。

- 草稿键由设备存储、账号、编辑模式和菜谱 ID 隔离；两端不跨设备同步。
- 编辑停止约 450 ms 后保存，离开/隐藏页面立即写入最新内容。
- 检测到草稿先让用户选择恢复或丢弃，选择前阻止编辑覆盖。
- 保存失败保留，成功或明确丢弃后清除；组件卸载不能重新创建已清除草稿。
- 只保存表单及上传后的 URL，不保存图片二进制或凭证；缓存空间不足要提示用户。
- `recipe-text` 负责格式转换，修改菜名等无关字段时保留多行步骤、步骤图片、复杂用量和零分钟。

## 助手状态

对话页显示今日剩余次数、每日上限和北京时间重置时间；两端共用服务器额度。全站暂停或用完也必须阻止发送，不能只判断个人剩余次数。

审核期间展示“确认需求 / 整理菜谱 / 核对内容”等固定进度，审核通过后展示完整回复与卡片。未被服务器受理的请求保留输入；超限、忙碌和网络错误给出具体提示。停止、新对话、删除对话均不能重置使用次数。

## 发布检查

- Web 检查 320 px 窄屏、390 px 深色手机和 1440 px 桌面布局，无横向溢出、挡住操作的导航或运行时异常。
- 小程序组件检查 320/390 px、浅色/深色；真机另测 iOS/Android 的键盘、昵称、头像、相机/相册和返回行为。
- 使用真实操作回归验证草稿、失败重试、头像同步、弹层焦点、站内信和额度，不只比对静态截图。
- 构建、lint 和客户端测试命令见开发指南，证据和边界见 [本轮审查报告](audit-report-arre-cook-2026-09-27.md)。

## 主题联调验收

`npm --prefix frontend test` 包含 Web 外观、两端色板一致性、按钮对比度、系统/手动模式、缓存异常、页面生命周期及图标/底栏/弹层同步测试。

`scripts/acceptance/mini-real-backend.cjs` 通过小程序实际页面处理函数与 `utils/api` 访问真实 Go HTTP 服务；只接受 localhost/127.0.0.1，必须配置独立验收数据库及账号，禁止对用户数据库执行。它使用微信运行时适配器，不提供 API 假数据，覆盖登录、推荐、午晚餐记录/去重、收藏、偏好、记录评价、明日菜单及其他业务读接口。环境变量：`ARRE_ACCEPTANCE_URL`（不含 `/api`）、`ARRE_ACCEPTANCE_ACCOUNT`、`ARRE_ACCEPTANCE_PASSWORD`。这项验收不代替微信真机渲染、微信登录或图片上传。
