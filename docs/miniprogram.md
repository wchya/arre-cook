# 微信小程序

## 工程配置

小程序名称为「arre食谱推荐小助手」，是 `miniprogram/` 下包含 24 个页面的原生 WXML/WXSS/JavaScript 工程。登录、菜谱、家庭、个人信息和站内信等主流程直接调用 Go API，不依赖 WebView。导入微信开发者工具时选择这个目录。项目 AppID 已配置；服务端 AppSecret 只放在根目录被 Git 忽略的 `.env` 中，通过 `WECHAT_APPID` 和 `WECHAT_SECRET` 传给后端。

默认 API 地址为 `https://cook.arrebyte.top/api`，配置在 `miniprogram/app.js` 的 `apiBase`。小程序原生登录页先尝试微信快捷登录；微信未绑定时可以用 QQ/Foxmail 邮箱验证码登录，并在同一账号上绑定新获取的 `wx.login` code。服务端从不把 AppSecret 下发给小程序。

登录页在发送验证码、调用微信登录或提交账号密码前，必须勾选并阅读小程序内置的《用户服务协议》和《隐私政策》。首次授权时还会调用微信 `wx.requirePrivacyAuthorize`，未同意不会获取 `wx.login` 凭证或提交邮箱/密码。协议页面为本地原生页面，不依赖外部域名。

提审时请在微信公众平台“测试账号/体验账号”或提审备注中提供一组临时可用的账号和密码。小程序已提供“已有密码？使用账号密码登录”入口，审核员可直接登录后体验食谱、饮食记录、家庭、AI 助手和站内信。审核账号应使用单独创建的普通测试账号，避免使用生产管理员账号；不要把真实密码写入 Git、截图或小程序代码。审核完成后立即修改密码或停用该账号。

原生小程序在本机保存会话令牌，并随 API 请求发送；退出或过期后回到原生登录页。食谱草稿仅在当前设备、当前账号保存，不跨设备同步；成功提交后清除。

## 微信公众平台

发布前配置以下平台信息：

- 图片上传只需在小程序后台「开发管理 → 开发设置 → 服务器域名」将 `https://cook.arrebyte.top` 加入 **request 合法域名** 和 **uploadFile 合法域名**。图片上传调用的是 `wx.uploadFile`，只配置 request 合法域名仍会失败。当前主流程无需业务域名，个人主体无需为上传图片配置 WebView。填写域名不带 `/api` 或末尾 `/`。
- 图片上传的开关不在代码里：在微信公众平台「开发管理 → 开发设置 → 服务器域名」将 `https://cook.arrebyte.top` 同时加入 **request 合法域名** 和 **uploadFile 合法域名**；再到「设置 → 服务内容声明 → 用户隐私保护指引」声明“选中的照片或视频信息”和“摄像头”。本小程序实际只调用 `wx.chooseImage` 选择图片，不选择或上传视频；`wx.uploadFile` 只把用户主动选中的头像、菜品图片或用餐记录照片上传到本人账号。域名配置与隐私指引需分别完成，并以微信后台实际生效/审核状态为准；代码上传不会自动修改平台指引。
- 隐私接口用途请按接口分别填写：**选中的照片或视频信息**：`用于上传用户主动选择的头像、菜品封面、菜品附图和用餐记录照片，以保存和展示对应内容；仅处理本次选择的图片，不读取其他相册内容，不上传视频。` **摄像头**：`仅在用户点击拍照并上传头像、菜品图片或用餐记录照片时使用，完成本次拍照后停止使用，不在后台开启或持续采集。`
- 开发者工具本地调试可以临时勾选「详情 → 本地设置 → 不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」，这只对本机生效，不能替代公众平台配置。
- 若启用微信快捷登录，服务器配置正确的 `WECHAT_APPID` 与 `WECHAT_SECRET`。
- 在微信开发者工具中确认工程 AppID 与服务器 AppID 一致，并完成主体认证、域名校验和隐私保护指引。
- 检查原生登录、邮箱验证码、退出、分享、草稿恢复，以及 iOS/Android 真机图片上传。

本地调试可以在开发者工具中按项目需要关闭域名校验，但体验版和正式版必须使用已备案并校验的 HTTPS 域名。`touristappid` 不能用于体验版或正式版。

## 上传代码

`docs/private.<AppID>.key` 是微信小程序代码上传 RSA 私钥，已从 Git 忽略并收紧为当前用户可读写。保留该文件在本机的 `docs/` 目录，不要复制到小程序工程、前端资源、镜像或环境变量中。它用于开发者工具/微信 CI 上传，不参与用户登录。

日常开发可直接用微信开发者工具预览和上传。若部署自动上传流水线，应由 CI 将这把私钥作为受保护文件挂载，并通过微信官方 `miniprogram-ci` SDK 上传；上传版本读取根目录 `VERSION`，与本次服务端部署一致。上传成功表示进入微信后台开发版本，之后仍需体验版检查、提交审核和正式发布。

## 昵称编辑回归

安装前端开发依赖后，在仓库根目录运行 `node --test scripts/tests/nickname-editor.test.cjs scripts/tests/recipe-drafts.test.cjs`，检查菜单隐藏与恢复、保存失败重试、快速重开和页面离开。昵称弹层控制的是 `custom-tab-bar` 的真实显示状态，页面底部占位保留以避免滚动跳动；菜单在关闭动画结束后恢复。输入框关闭自动顶页，由键盘高度驱动面板位置，保存和取消按钮放在不会收缩的底部插槽。

上传后仍需在 iOS 体验版检查深浅色、键盘展开和收起、取消、保存、切到后台后返回。服务端容器部署不会替换手机上的小程序包，微信后台上传成功也不等于正式版已发布。

## 草稿与资料回归

「关于我们」可从登录页和「我的」进入，展示平台特色、用法、常见问题和协议。对话页展示两端共用的每日次数，识别个人限额、全站限额及暂停状态；审核阶段显示进度，完整回复通过审核后再展示正文与菜品卡片。

- 草稿：账号/菜谱隔离，离开立即保存，恢复或丢弃，失败保留、成功清理；上传中禁止提交。
- 菜谱编辑：仅修改名称、封面时，保留步骤图片、多行做法和原有用量。
- 「我的私房菜」展示本人创建、当前仍有权访问的个人和家庭菜谱，返回后同步最新内容；入口数量、列表和菜系统计使用相同范围。家庭菜谱显示共享标记，退出家庭后不会凭作者身份继续访问该家庭内容。
- 菜谱编辑页支持视频 / 字幕提炼，使用可取消的 SSE 请求，不占用普通接口的 20 秒超时。保留原有内容与提炼期间的编辑，结构化食材与步骤随草稿恢复；详见 [视频做法提炼](video-recipes.md)。该功能读取用户提供的公开视频链接，不调用手机视频选择或麦克风接口。
- 点击底部「菜谱」会清除旧的私房、分类和搜索筛选；从菜谱详情返回时保留主动选择的范围。空列表提供「查看全部菜谱」入口。家庭页面的「分享我的私房菜」使用 `scope=private`，只列出可复制分享的个人原件。
- 更换头像后，「我的」与「账号与安全」应显示同一份资料。
- 站内信详情反复打开保持单层展示。

浏览器与组件模拟不能替代 iOS/Android 微信里真实的键盘、授权与图片上传测试。

菜谱入口回归：`node --test scripts/tests/recipe-visibility.test.cjs`，检查私房空列表恢复、跨 Tab 清除筛选和详情返回时保留范围。服务端对应回归为 `cd backend && go test ./internal/routes -run TestPersonalRecipeCountMatchesCollectionAfterFamilySharing`。
