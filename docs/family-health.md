# 家庭模式与饮食报告

## 家庭模式

登录后从「我的 → 我的家庭」创建家庭。创建者可以按邮箱邀请成员；邀请 7 天有效，只能由该邮箱对应的账号接受。创建者可以撤销邀请、移除成员、转让家庭或解散家庭；成员可以退出。一个账号同时只能属于一个家庭。

家庭空间共享菜谱、未来 7 天的午晚餐菜单和买菜清单。私房菜可以复制到家庭菜谱，原菜谱继续属于本人。家庭菜谱由作者或家庭创建者管理。个人收藏、用餐记录、饮食日记、偏好和 AI 对话不会因为加入家庭而共享。家庭成员的个人 Agent 令牌仍只代表该成员自己。

## 自愿饮食档案

饮食记录页的「我的饮食档案」可填写目标意愿、常见就餐方式、过敏食材和生活方式/宗教禁忌食材。均可跳过；空白表示未提供，不表示已确认没有过敏。每次修改需本人核对确认，另一页面已修改时会提示重新载入。

档案独立于原饮食偏好，仅本人可查看，不自动共享给家庭和 AI。过敏和禁忌用于个人推荐、明日推荐、周菜单及报告计划的食材筛选，不因候选少而放宽；原有偏好继续生效。筛选按菜谱文本匹配，仍需核对配料和交叉接触；手动记餐与家庭菜单需自行确认。目标仅记录意愿，目前不生成每日热量或营养摄入目标。

可以清除档案及所有历史版本，饮食记录与原偏好保留。已安排菜谱若与新忌口冲突，会显示不可用，需要重新安排。账号导出包含当前档案与历史，注销一并删除。接口与数据边界见 [自愿健康档案](health-profile.md)。

## 饮食记录与报告

首页显示最近七天的记录摘要，可直接进入周报；摘要与完整报告共享统计口径，不调用模型。

「我的 → 饮食记录与报告」支持填写日期、餐次、实际吃的食物、个人份量、菜系、食物类别和备注，无须先建菜谱。可以修改记录，或用“今天也吃了”复用上一餐内容；复用后仍需确认日期、餐次和份量。

“用一句话记餐”可把一次实际饮食描述整理成多个待确认食物项。只有本次文字会发送给已配置AI；核对原文证据、日期、餐次和个人实际份量后，勾选确认才保存。份量未知可留空，整盘、他人份量和剩余未吃部分不能当作自己摄入。保存后可编辑日记补充标签/标准食物及营养用量。无模型或整理失败时仍可手动记录。额度与数据说明见 [文字记餐草稿](health-meal-drafts.md)。

近 7 天和 30 天报告按北京时间统计。日历可查看每天的来源记录，分别显示餐次、食物项和原始条目。主餐按日期/餐次归组；独立加餐可用事件标识区分。菜谱记录与日记疑似重复时，需本人确认关联后才按一个食物项计算，不自动删除原始记录。旧 API 的 `meal_count` 仍表示原始条目数。

日历中早、午、晚餐分别显示“尚未记录”“已有实际记录”或本人确认的“明确未吃”。未吃可撤销，之后补记同一餐会自动清除该标记；删除补记也不会恢复标记。未吃不增加餐数、食物项或零营养摄入。只有未吃标记、没有实际食物记录的日子暂不能确认全天完整。

确认当天已记录全部食物、饮料和加餐后，可标为“已确认完整”。后续补记、修改或删除记录会使确认失效；有三条记录不等于吃了三餐，也不会自动判定全天完整。尚无份量或营养数据时只观察饮食习惯，不估算热量或判断营养缺口。

可选录入自己的包装营养标签，填写每 100 克或每 100 毫升数据、来源说明和食物状态，再填写实际食用量。支持能量、蛋白质、碳水、脂肪、膳食纤维和钠；千焦可在客户端换算为千卡。未知项留空，标签未经平台核验，估计份量会单独标明。克与毫升、生与熟不自动换算。

报告先区分食用量依据：称量/量取、标准份量估算、其他估算、仅文字份量与份量未知，按去重食物项计数。文字描述不会自动成为克重，称量也不代表营养值已核验。

报告逐项展示已知部分合计与覆盖食物项。7 天至少 4 个完整且该项营养数据全覆盖的日子才显示日均，30 天至少 18 日；这些是产品数据门槛，不是医学标准。标签修正或删除不改历史摄入快照；日记更改食物或份量后需重新选择标签，复用到今天也需重新填写实际食用量。个人标签与营养快照包含在账号导出/注销中。

可以用“新建混合配方”记录酸奶麦片等无需加热的混合食品。先录入所有原料的个人标签或添加标准食物，再选择每项原料、加入量、成品总克重，并确认没有弃去固体或液体。保存配方后填写自己吃的成品克重，报告按均匀混合比例估算。标签和配方都可以修正或删除，历史摄入保留原来的原料版本与来源。某项营养只要有一个原料未知，配方该项也为未知。煎炒、弃汤、沥水等暂不适用。

记餐时也可“查找标准食物”，按名称、别名和生熟状态搜索已配置目录，核对来源、许可及核验信息后添加到自己的食物。需填写实际可食部分用量；条目若有核验标准份量，可选择“一碗/一个”等并填写数量（例如0.5），服务端换算且明确标为估算，报告保留换算依据。不支持自动去皮去骨、生熟或克/毫升换算。个人副本只读；目录更新不会替换旧副本，撤下只停止搜索与新添加。标准食物也可作为混合配方原料，报告保留各原料的来源版本。尚无匹配目录时可继续普通记餐或录入包装标签。

报告还可对比紧邻的上一段 7/30 天：按相同星期几匹配完整且该项营养齐全的日子，优先取最近日期。达到 4/18 对才显示配对日均和绝对差值，并可展开查看日期。配对均值可能与全部完整日均不同；没有足够可比日时显示原因。升降不代表健康改善或恶化。

报告推荐可选择今天起七天内的早/午/晚餐，加入个人菜单与买菜清单。显式安排独立保存，替换对应餐次的随机推荐，重新生成菜单不会丢失。当前周以外的安排先在报告“已安排与复盘”中查看，进入对应自然周后在周菜单展示。现有买菜页展示今明两天的食材，较远日期临近后自动进入该视图。早餐仅展示本人明确采纳的安排，不自动生成随机早餐。计划不等于实际吃过；当天或过去的可用计划可在报告里单独确认“记为吃过”，之后仍可补充个人份量和营养。有相同日期/餐次/菜谱的用餐记录时才展示“已有记录支持完成”。撤销计划不会删除实际用餐记录。

报告只反映用户实际记录。未标注某类食物不代表没有吃。过敏和忌口过滤沿用现有推荐引擎，采纳计划时再次校验；仍需本人核对食材。没有标准营养数据和审核规则时，不提供精确营养目标或医疗诊断。

第三方 Agent 通过个人令牌和 MCP 或函数调用接口访问 `list_food_journal`、`log_food_journal`、`delete_food_journal`、`get_health_report`；站内助手使用同一工具注册表。工具按令牌所属用户隔离并受 scope 限制。菜谱记录工具 `log_meal`、`list_meal_records` 支持早餐；周菜单工具返回显式早餐安排。餐次未吃标记仅由个人登录页面修改。集成方式见 [Agent 接口](agent-api.md)。

需要 Agent 代为管理菜谱时，可额外授予 `dishes:write`，使用 `create_private_recipe`、`update_private_recipe` 和 `delete_private_recipe`。这些工具只操作本人私房菜，不会把菜谱公开或共享到家庭；删除前助手应先征求确认。
