# 助手安全与额度

适用于 Web、小程序站内对话及外部食谱工具接口。视频做法提炼复用本页的 AI 额度、并发和审核规则，独立读取边界见 [视频做法提炼](video-recipes.md)。

## 使用次数

| 配置 | 默认 | 管理员可设置 | 作用 |
| --- | --- | --- | --- |
| `assistant_daily_limit` | 20 | 0–20 整数 | 每账号每日站内提问上限，Web 与小程序共用 |
| `assistant_site_daily_limit` | 200 | 0–10000 整数 | 所有账号的每日总预算 |
| `AGENT_RATE_LIMIT` 环境变量 | 120 | 1–600 | 外部食谱工具每账号每分钟请求数 |

前两项在「管理 → 设置」保存；设为 0 可暂停站内助手。非管理员只能读取自己的额度，不能修改上限。外部限流配置为非正数时回落到 120，超过 600 时按 600 执行。

每日按北京时间 00:00 重置。`assistant_usages` 的 `(user_id, usage_date)` 联合主键持久计数，`user_id=0` 保留给全站预算；用户和全站计数在同一事务中预留，一方用完时另一方不增加。计数不会因刷新、退出、换端、删对话或部署而重置。

每条已受理请求计 1 次，包括模型审核拒绝、上游失败和用户中途停止。登录失败、非法参数、本地短语拒绝、他人会话和未取得并发位置的请求不计每日次数。先预留再访问模型，防止失败重试被用于无限消耗。历史计数与调用审计保留约 180 天，定时任务每小时清理；注销账号清理本人记录，全站已消费计数继续保留。

## 资源和入口限制

- 站内对话只接受用户登录 JWT，PAT 和短期 Agent 令牌不能使用站内模型。
- 站内请求仅接受 `message` 与可选 `session_id`，最多 1000 字、16 KiB 请求体，拒绝自行提供模型、系统消息、工具或地址。
- `assistant_leases` 用随机 owner 和过期时间限制同账号同时 1 请求、全站同时 4 请求；请求总超时 90 秒、租约 2 分钟，取消后释放，进程退出时到期恢复。数据库不可用时拒绝请求。
- 认证前对 AI、Agent、登录和凭证管理入口按来源 IP 限流 240 次/分钟；登录另有 30 次/10 分钟保护，站内对话另有每账号 60 次/分钟保护。
- `Authorization` / `X-Agent-Token` 最多 4096 字节；登录与聊天请求体最多 16 KiB，其他受保护接口最多 256 KiB；HTTP 请求头最多 32 KiB。
- 上游不跟随重定向；单轮响应最多 1 MiB、正文 16 KiB、8 个工具调用、单个工具参数 32 KiB；一轮提问最多 4 轮生成、12 次工具调用。
- 外部 REST、MCP、PAT 和短期会话的预算按账号共享；MCP 每批最多 10 条，执行前预留全部额度，预算不足整批拒绝。

## 内容审核与写入

服务端固定角色只处理食谱、可食用食材、烹饪、厨房食品安全、饮食偏好、菜单、买菜清单和饮食记录。用户不能从客户端改模型或系统提示。昵称、偏好、历史和菜谱内容均作为不可信数据传递。

1. 本地检查规整空白、全角、零宽与标点，识别敏感短语、明显无关请求和提示词覆盖；普通菜名、厨刀、啤酒鸭和食品杀菌问题保持可用。
2. 模型输入审核仅接受正常结束的精确 `ALLOW` 或 `BLOCK`，每次审核最多 20 秒、512 个 token（兼容上游将思考过程计入输出预算）。服务失败、截断、格式不符或不确定时拒绝继续。
3. 根据当前提问筛选可用写入工具，否定或仅询问操作方法不作为授权。每次拟写入再审核操作和参数；聊天不提供删除工具。
4. 工具参数和返回内容先解析 JSON 再检查，避免通过 Unicode 转义藏入指令。历史角色只接受用户与助手，异常历史内容跳过。
5. 完整回复与菜品卡片审核通过后才保存并展示。审核前只返回固定状态、固定工具名称与服务端生成的事件 ID；上游错误正文不返回用户。

未配置模型时保留本地食谱推荐与饮食报告，写入操作提示到页面填写。本地推荐同样经过本地内容检查。普通问候使用固定的食谱助手介绍。

内容拒绝日志只记录账号、检查阶段和结果，不保存被拒绝的提问原文。正常对话、工具审计和必要模型处理范围见应用内隐私政策。

## 浏览器来源与代理

生产环境必须配置正确的 `PUBLIC_URL` 与 `CORS_ORIGINS`。AI 入口只接受显式配置的浏览器 Origin，通配符 `*` 不给予信任；响应使用 `no-store`，页面通过 `frame-ancestors 'self'` 与 `X-Frame-Options: SAMEORIGIN` 限制外站嵌入。开发环境允许本机 Vite 与 API 使用不同的回环地址/端口。

原生微信和 CLI 通常没有 Origin，继续通过令牌类型、权限、账号归属、次数和资源上限限制。Origin、Referer、User-Agent 都不是秘密，不能证明调用方身份。持有人主动转发自己的有效凭证无法完全阻止，但转发仍占用本人及全站预算，无法获得其他用户数据或无限模型调用。公开注册开启时，来源限流和全站预算共同限制多账号消耗。

HTTP 代理必须覆盖来自公网的伪造转发头，并正确传递客户端 IP。`TRUSTED_PROXIES` 应只覆盖实际代理来源；每分钟 IP/外部 Agent 限流目前在单进程内，未来增加应用副本时需迁入共享限流存储。每日额度与并发租约已经跨实例共享。

模型审核和短语过滤都有误判与绕过可能，不能用“绝对防破解”描述。上线使用真实模型分别验证正常食谱、无关提问、敏感提示和越权写入；出现新误判时针对具体样例调整并保留回归用例。

## 客户端协议

| 场景 | HTTP / code | 客户端行为 |
| --- | --- | --- |
| 个人或全站每日额度不足 | 429 / 42901 | 读取 `data.quota`，保留未发内容，展示恢复时间或暂停原因 |
| 同账号/全站并发已满 | 429 / 42902 | 保留输入，稍后重试，`Retry-After: 5` |
| 来源/短期限流 | 429 / 42900 | 停止重试并提示稍后使用 |
| 外站 Origin | 403 | 提示从食谱站或小程序访问 |
| 本地检查拒绝或非法参数 | 400 | 展示原因，不消费每日次数 |
| SSE 中的模型审核或处理失败 | `error`，随后 `done` | 展示友好提示，已受理请求计入次数 |

SSE 事件顺序：`quota` → `status` → `session` → `status` / `tool_start` / `tool_end` → `delta` → 可选带 `card` 的 `tool_end` → `done`。v0.10.1 为兼容尚未升级的微信版本，审核后的卡片使用既有 `tool_end.card` 格式；新客户端也支持 `cards` 事件，但服务端不同时发送两种格式，避免重复。审核被拒绝时可能只有 `quota`、`status`、`error`、`done`。客户端必须兼容无工具、无卡片和中途失败。

`quota` 包含 `limit`、`used`、`remaining`、`reset_at`，全站暂停或用完时附带 `blocked_reason: "site_limit"`。即使个人 `remaining > 0`，存在 `blocked_reason` 也禁止发送。
